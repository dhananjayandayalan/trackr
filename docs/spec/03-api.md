# 03 · REST API

Base URL: `/api/v1` (served by `apps/api` on :8080; the Vite dev server proxies `/api`). JSON only. OpenAPI 3.1 document at `/v3/api-docs`, UI at `/swagger-ui.html` (dev profile only), generated by springdoc-openapi.

## 1. Conventions

| Topic           | Rule                                                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Naming          | JSON fields `camelCase`; paths plural nouns; issues and projects addressed by **key** (`MAR`, `MAR-131`), everything else by id                                    |
| Auth            | Session cookie `TRAKR_SESSION` (HttpOnly, Secure in prod, SameSite=Lax). Unauthenticated → 401 problem                                                             |
| CSRF            | Cookie `XSRF-TOKEN` (readable by JS), header `X-XSRF-TOKEN` required on POST/PUT/PATCH/DELETE                                                                      |
| Concurrency     | Every mutable resource returns `ETag: "v<version>"`. PATCH/DELETE require `If-Match`. Mismatch → **412** with the current resource in the problem body (`current`) |
| Idempotency     | POSTs that create (issues, comments, projects) accept `Idempotency-Key` header (UUID). Same key within 24 h returns the original response (stored in Redis)        |
| Pagination      | Cursor based: `?limit=50&cursor=<opaque>`; response `{ items, nextCursor }`. Cursor = base64url of the last row's sort keys                                        |
| Partial updates | `PATCH` with JSON Merge Patch semantics (`application/merge-patch+json`): absent = unchanged, `null` = clear                                                       |
| Time            | ISO-8601 UTC strings (`2026-10-22T13:20:00Z`); dates `YYYY-MM-DD`                                                                                                  |
| Warnings        | Successful responses may include `warnings: string[]` (e.g. `WIP_LIMIT_EXCEEDED`)                                                                                  |
| Rate limits     | 20 req/s per user burst 40 (Redis token bucket); 429 with `Retry-After`                                                                                            |

## 2. Errors — RFC 9457 problem details

```json
{
  "type": "https://trakr.dev/problems/transition-not-allowed",
  "title": "Transition not allowed",
  "status": 409,
  "detail": "MAR-131 cannot move from Done to In review.",
  "instance": "/api/v1/issues/MAR-131/move",
  "code": "TRANSITION_NOT_ALLOWED",
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "errors": [{ "field": "summary", "message": "must not be blank" }]
}
```

| HTTP | `code` examples                                                                          |
| ---- | ---------------------------------------------------------------------------------------- |
| 400  | `VALIDATION_FAILED` (with `errors[]`), `TQL_SYNTAX_ERROR` / `TQL_INVALID_QUERY` (with `position`, `expected[]`), `CURSOR_EXPIRED` |
| 401  | `UNAUTHENTICATED`                                                                        |
| 403  | `FORBIDDEN`, `CSRF_INVALID`                                                              |
| 404  | `NOT_FOUND` (also used when the caller can't see the resource — don't leak existence)    |
| 409  | `TRANSITION_NOT_ALLOWED`, `PROJECT_KEY_TAKEN`, `SPRINT_ALREADY_ACTIVE`, `INVALID_PARENT` |
| 412  | `VERSION_MISMATCH`                                                                       |
| 413  | `ATTACHMENT_TOO_LARGE`                                                                   |
| 429  | `RATE_LIMITED`                                                                           |

### 3.5 Comments

`GET /issues/{key}/comments?cursor` · `POST /issues/{key}/comments {bodyHtml}` · `PATCH /comments/{id}` (author only, `If-Match`) · `DELETE /comments/{id}` (author or P:admin).
Body HTML is sanitised server-side with an allow-list (p, br, strong, em, code, pre, ul, ol, li, a[href], span[data-mention-id]).

### 3.6 Attachments (browser uploads straight to S3)

1. `POST /issues/{key}/attachments/uploads {fileName, contentType, sizeBytes}` → `{uploadId, objectKey, url, headers}` (presigned PUT, 5 min).
2. Browser `PUT url` with the file.
3. `POST /issues/{key}/attachments {uploadId}` → api `HEAD`s the object to confirm size/type → 201 `Attachment`.
   `GET /attachments/{id}/content` → 302 to a presigned GET (1 min). `DELETE /attachments/{id}`.

## 4. Server-Sent Events

`GET /api/v1/projects/{key}/stream` (P:viewer) and `GET /api/v1/me/stream`.
Headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`.

Wire format (one event):

```
id: 0190f3b2-7c1e-7a51-9f00-3b1d2c9e4a10
event: issue.moved
data: {"key":"MAR-131","sequence":42,"statusId":"…","sprintId":"…","rank":"a0V","actorId":"…"}

```

- `id` = event envelope id. The browser sends it back as `Last-Event-ID` on reconnect; the server replays missed events from a 5-minute Redis stream buffer per project (`XRANGE`), else sends `event: resync` telling the client to refetch.
- Heartbeat comment line `: ping` every 15 s keeps proxies from closing the connection.
- Event names (project stream): `issue.created`, `issue.updated`, `issue.moved`, `issue.deleted`, `comment.added`, `sprint.started`, `sprint.completed`, `sprint.updated`, `workflow.changed`, `board.changed`, `presence` (who is viewing the board).
- Event names (me stream): `notification`, `unread-count`.
- The `data` payload is the event's `data` from 04-events (minus private fields) plus `sequence`.

## 5. OpenAPI → TypeScript

springdoc generates the document from controllers + records. Rules so the generated types are good:

- Every record field that can be null is annotated `@Nullable` (JSpecify) → becomes optional/nullable in TS.
- Enums are Java `enum`s serialised as lowercase strings via `@JsonValue`.
- Each controller method has `@Operation(operationId = "moveIssue")` — operation ids become function names.
- The frontend runs `pnpm api:types` → `openapi-typescript http://localhost:8080/v3/api-docs -o src/shared/api/schema.d.ts`.
