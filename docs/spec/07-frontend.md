## 2. Routing (TanStack Router, code-based)

| Path                               | Component             | Loader prefetches                              |
| ---------------------------------- | --------------------- | ---------------------------------------------- |
| `/login`                           | LoginPage             | — (public)                                     |
| `/`                                | HomePage              | me/stats, me/work?tab=assigned, projects       |
| `/projects`                        | ProjectsPage          | projects                                       |
| `/projects/new`                    | CreateProjectPage     | key suggestion on input                        |
| `/p/$projectKey`                   | ProjectShell (layout) | project (statuses, members)                    |
| `/p/$projectKey/board`             | BoardPage             | board (active sprint)                          |
| `/p/$projectKey/backlog`           | BacklogPage           | backlog                                        |
| `/p/$projectKey/timeline`          | TimelinePage          | timeline                                       |
| `/p/$projectKey/reports`           | ReportsPage           | burndown for active sprint                     |
| `/p/$projectKey/settings/$section` | SettingsPage          | workflow / members                             |
| `/p/$projectKey/issues/$issueKey`  | IssuePage (full page) | issue, comments                                |
| `/issues?tql=&filter=`             | IssuesPage            | search (search params validated with a schema) |

- The board and backlog open issues as a **side panel** via search param `?issue=MAR-131` (keeps the board mounted, shareable URL).
- A root `beforeLoad` checks `me`; unauthenticated → redirect to `/login?next=…`.
- Every page route is lazy (`lazyRouteComponent`) → one chunk per screen.
- `defaultPreload: 'intent'` → hovering a link prefetches its loader data and code.
- View Transitions: `router.navigate({ viewTransition: true })` for page changes; CSS in 08 §7.

## 3. Data layer (TanStack Query)

- `QueryClient` defaults: `staleTime: 30_000`, `gcTime: 5 * 60_000`, `refetchOnWindowFocus: true`, `retry: (n, err) => n < 2 && !(err instanceof ApiError && err.status < 500)`.
- Key factories per feature, e.g.
  `boardKeys = { all: ['board'], view: (projectKey, sprint) => ['board', projectKey, sprint] }`.
- Loaders: `ensureQueryData(boardQuery(projectKey, 'active'))`.
- **API client**: `openapi-fetch` with the generated `paths` type → every call is fully typed (`client.POST('/api/v1/issues/{key}/move', { params: { path: { key } }, body })`).
  Middleware: adds `X-XSRF-TOKEN` from the cookie on mutations; turns `application/problem+json` into a thrown `ApiError` (status, code, detail, errors, current).

### Optimistic move (the most important mutation)

```
onMutate(vars):
  await queryClient.cancelQueries(boardKeys.view(...))
  const previous = queryClient.getQueryData(boardKeys.view(...))
  queryClient.setQueryData(..., board => applyMove(board, vars))   // pure function, unit tested
  return { previous }
onError(err, vars, ctx):
  queryClient.setQueryData(..., ctx.previous)
  toast(err.code === 'TRANSITION_NOT_ALLOWED' ? 'That move isn't allowed' : 'Couldn't move — reverted')
onSuccess(result):
  patch the card with the server's rank + version (server is authoritative)
  if result.warnings includes WIP_LIMIT_EXCEEDED → column warning state
onSettled: nothing (SSE keeps others fresh; we avoid refetching the whole board)
```

### Live updates (SSE → cache)

- `ProjectShell` opens `sse.ts` → `EventSource('/api/v1/projects/MAR/stream', { withCredentials: true })`.
- Each event's `data` is parsed with a zod schema (never trust the wire) and dispatched:
  - `issue.moved/updated/created` → patch `board` and `backlog` caches if `sequence > card.version`; else ignore.
  - `issue.deleted` → remove card.
  - `sprint.*`, `workflow.changed`, `board.changed` → `invalidateQueries` for that project.
  - `resync` → invalidate everything under the project.
- Cards changed by others get `data-flash` for 1 s (CSS animation).
- Connection status shown as a small dot in the board header (connected / reconnecting).

## 4. Drag and drop (Pragmatic drag and drop)

- `draggable({ element, getInitialData: () => ({ key, version }) })` on each card.
- `dropTargetForElements` on each card (to compute before/after using `attachClosestEdge`) and on each column body (drop into empty column).
- `monitorForElements` at board level → on drop compute `{toStatusId, beforeKey, afterKey}` → run the optimistic mutation.
- `autoScrollForElements` on the board scroller.
- Disallowed targets (no transition from current status) get `data-drop-disabled` and reject the drop.
- Keyboard alternative: card menu → "Move to…" (accessibility requirement).

## 5. Ranking on the client

`rank.ts` implements fractional indexing (`generateKeyBetween(a, b)` over base-62 digits) **identically** to `Rank.java`. The client computes a provisional rank for the optimistic update; the server recomputes from current neighbours and the response overwrites it. Shared test vectors (`rank-vectors.json` in `docs/spec/fixtures/` — created in phase 07) are run by both Java and Vitest tests.

## 6. Big lists

Backlog and search results use `@tanstack/react-virtual` (`useVirtualizer`, estimated row height 44 px, overscan 8). Board columns are not virtualised until > 150 cards in a column.

## 7. Forms

Native `<form action={formAction}>` with `useActionState`; the action calls the mutation and returns `{errors}` mapped from the problem's `errors[]` onto fields. `useFormStatus` drives button pending state. Client-side validation = HTML attributes (`required`, `pattern`, `maxlength`) plus `setCustomValidity` for cross-field rules.

## 8. Build and performance settings

- Vite 8 (Rolldown) with `@vitejs/plugin-react` + `babel-plugin-react-compiler` per the plugin's current docs.
- `build.target: 'baseline-widely-available'`, CSS minified by Lightning CSS (`css.transformer: 'lightningcss'`, targets from browserslist `>0.5%, last 2 versions, not dead`).
- Manual chunks: `react` + `react-dom` + router + query → `vendor`; Tiptap + Yjs → `editor` (only loaded when an issue opens).
- Fonts: self-hosted woff2, `font-display: swap`, preload Inter 400/600.
- Budget check in CI: fail if initial JS > 180 KB gzip.

## 9. Dev server

`vite.config.ts` proxy:

- `/api` → `http://localhost:8080` (with `ws: false`; SSE works through the proxy).
- `/oauth2`, `/login/oauth2` → `http://localhost:8080`.
- `/collab` → `ws://localhost:8081` (`ws: true`).
  Same-origin in dev means cookies and CSRF behave exactly as in production behind Caddy.
